# 설계 근거

탐색·분석·게시를 3열로 배치하여 검토 중 출처와 최종 댓글을 함께 볼 수 있게 했습니다. 패널은 GridSplitter로 조절하며 긴 내용은 스크롤합니다. 로딩 중 선택/편집/중복 실행을 막고 작업 취소와 상태 영역은 유지합니다. API 키는 비밀번호 입력 필드로만 취급합니다.

댓글 작성은 출처의 범위를 좁히고 확실한 근거를 제공하는 방향으로 구현했습니다. 영상 자체를 확인하지 못했으므로 제목/설명 기반임을 표시하고 연속 구절 인용을 검증합니다. 시청자 댓글은 보조 맥락입니다. 영상을 실제로 봤거나 사주를 이용한 것처럼 위장하지 않으며 운명원 홍보임을 밝힙니다.

브라우저 자동화는 독립 프로필, 사용자가 직접 로그인, 채널 핸들 확인, 입력 후 최종 승인으로 구성했습니다. DOM 구조나 계정을 확정하지 못하면 게시를 중단합니다. 개별 댓글 ID 링크까지 확인하지 못한 상태는 성공으로 간주하지 않습니다.

DB와 외부 게시 사이에는 원자적 트랜잭션이 없으므로 중복 게시보다 누락을 선택하는 보수적 보호를 둡니다. Posting 상태를 클릭 전에 저장하고 불확실한 시도를 계속 차단합니다. 하루 상한은 성공 수 대신 예약 시도 수를 기준으로 계산해 실패를 반복해도 게시량이 늘지 않게 했습니다.

사용자 프로필·DB·키는 사용자 AppData에 두어 설치/제거와 분리합니다. 기본 키/모델을 코드로 주입하지 않으며 기본 모델명은 설정에서 교체할 수 있습니다. 브라우저 세션과 설치 폴더를 통째로 Git에 넣지 않습니다.
